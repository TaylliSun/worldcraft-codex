# Worldcraft Codex 2.2.0-rc.18

## 自包含工程包

- 新增单文件 `.wcodex` 完整工程包，包含项目数据、图片、音频、地图素材和资料文件；旧 `.wcodex.json` 继续兼容打开。
- 工程包使用流式 ZIP64 读写，不把大型资源整体载入内存；`manifest.json` 记录独立包版本、工作区 schema、项目数据与每项资源的大小和 SHA-256。
- 保存先写同目录临时文件，重新打开并逐项验证后才原子替换旧包；失败另存不会损坏已有工程包。
- 打开时先在资源目录的隔离临时目录完成清单、路径、大小和哈希验证，再安装资源并提交 SQLite；非法路径、重复/未声明条目、异常压缩比和内容篡改均在当前项目变化前拒绝。

## 资源安全

- 普通资源导入改为 SHA-256 内容寻址；相同文件只保存一次，地图优化图片继续保留 `map-<hash>` 命名兼容。
- 工程包导入按内容复用已存在资源，发生短哈希命名冲突时使用完整哈希回退，绝不覆盖不同内容。
- 资源库显示缺失、大小变化、SHA-256 不符和已验证状态，并提供重定位/替换；选择不同内容时需要再次确认。
- 重定位会同步修复地图、图层、标记和富文本中的 `worldcraft://asset/` URL；共享文件的资源记录一起修复，删除单条记录不会误删仍被其他记录使用的文件。

## 备份与写入顺序

- 项目检查新增“完整备份”，在备份目录保留最近 5 个含资源 `.wcodex`；高频自动备份和 AI 检查点继续使用快速数据快照，界面明确标注“仅项目数据”。
- 完整备份与快速快照使用同一列表恢复；完整备份恢复前会再次校验资源，快速快照不会声称能够补回丢失文件。
- 打开工程和恢复备份前先冲刷当前修改；外部数据提交期间主进程屏蔽迟到保存，读取也等待保存队列清空，避免旧自动保存覆盖新项目。

## 验证

- 工程包单元与故障注入通过 36 项断言、12 个场景，覆盖去重、直接 URL 资源、缺失资源、未来 schema、非法路径、未声明条目、冲突归档声明、项目/资源篡改、临时目录清理和失败原子替换。
- Electron 干净目录往返通过 31 项断言、3 次启动：删除源用户目录后，项目、资源、地图 URL、完整备份、恢复、重定位、重启持久化与 UI 状态保持完整；同一套断言已再次针对打包后的 `Worldcraft Codex.exe` 通过。
- 1000 个逻辑资源、20 个 1 MiB 实体文件压力门禁通过 15 项断言；创建、全校验、干净提取和重复复用均低于发布预算。
- 旧 JSON 项目、schema 16 SQLite、现有快速备份和发布净化格式保持兼容。

## 隐私边界

- `.wcodex` 是完整创作工程，不是公开发布格式：它包含正文、秘密字段、开发备注、测试数据和 AI 私有记忆，且当前不加密。
- API Key 仍由系统凭据存储单独保护，不进入 `.wcodex`、SQLite、任何备份、日志或诊断包。
