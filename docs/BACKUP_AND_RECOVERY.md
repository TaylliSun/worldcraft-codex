# 备份与恢复

## 三种保护方式

1. **快速数据快照**：自动保存、AI 检查点和“快速快照”使用 `.wcodex.json`，写入快，保存正文、设定、关系和历史，但不复制图片、音频等资源文件。
2. **完整工程备份**：在“项目检查”中点击“完整备份”，生成包含项目数据和全部可用资源的 `.wcodex`；本地最多保留最近 5 份，列表会显示资源是否完整。
3. **另存完整工程包**：在“导出”中点击“保存完整工程包”，把自包含 `.wcodex` 保存到其他磁盘，用于跨机器迁移和离线归档。

不要只依赖同一磁盘上的自动快照。重要项目应定期把 `.wcodex` 复制到另一块磁盘或可信备份介质。

## 恢复备份

1. 打开“项目检查”，在备份列表确认类型、时间、对象数量和资源完整度。
2. 选择“恢复此备份”。软件会先冲刷当前修改并生成 `before-restore` 保护副本。
3. 完整工程备份会先在临时目录校验清单、大小和 SHA-256，再按内容复用或安装资源；校验失败不会改动当前项目。
4. 快速数据快照只恢复项目数据。原资源目录仍保留，但快照无法补回已经丢失的文件。
5. 恢复后重新运行项目检查，并抽查最近编辑、地图底图和资源预览。

## 跨机器迁移

1. 在源电脑保存 `.wcodex` 完整工程包，确认提示中没有缺失资源。
2. 在目标电脑选择“打开工程包”。无需手动复制 `assets/`。
3. 软件会把资源改为内容寻址文件名，并同步修复地图、图层和正文中的 `worldcraft://asset/` 引用。
4. 旧 `.wcodex.json` 仍可打开，但它没有资源二进制；若只能使用旧文件，还需要另行找回原 `assets/` 目录。

## 资源修复

1. 项目检查会报告文件缺失、大小变化和已记录 SHA-256 不符。
2. 打开对应资源，选择“重定位文件”或“替换文件”。
3. 若所选文件与原哈希不同，软件会要求明确确认；确认后更新完整性记录。
4. 多个资源记录共享同一物理文件时，重定位会一起修复共享引用；删除其中一个记录不会误删仍在使用的文件。

## 从迁移副本恢复

1. 在“SQLite 与搜索诊断”中选择迁移保护副本。
2. 确认恢复。软件先把当前数据库复制到 `backups/rollbacks/`。
3. 旧数据库恢复后会重新升级到当前 schema。
4. 检查 `quick_check`、对象数和全局搜索覆盖。

## 无法启动时

1. 不要删除用户数据目录。
2. 复制整个用户数据目录到安全位置，保留 `backups/`、`assets/` 和 SQLite 文件。
3. 查看 `logs/worldcraft.log.jsonl` 的事件名称。
4. 可在空用户目录启动软件，再打开最近的完整 `.wcodex`。
5. 若只有快速 JSON 快照，它可以恢复项目数据，但丢失资源仍需在资源详情中重新定位。
