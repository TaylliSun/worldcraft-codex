# Worldcraft Codex 全工程审计与后续目标

审计日期：2026-07-16
审计基线：2.2.0-rc.17
执行版本：2.2.0-rc.20
范围：知识库、长篇写作、剧情与任务、关系、时间线、AI、资源、导出、SQLite、桌面打包和发布门禁。

## 基线结论

审计开始时，类型检查、领域测试、SQLite、迁移矩阵、1 万条目性能、生产构建、400 项 Electron 冒烟断言、便携版冷启动和覆盖升级全部通过。当前主要风险不是已有测试红灯，而是跨模块工作流尚未完全闭环。

## 已发现目标

### P0：发布与长期创作安全

1. **完整工程可携带性（rc.18 已完成）**：自包含 `.wcodex` 已携带项目数据与资源，并保留旧 `.wcodex.json` 兼容入口。
2. **稳定正文引用**：结构化引用使用 ID，但正文 `[[标题]]` 仍会受重名和改名影响，需要升级为 ID 支撑的编辑器节点并兼容旧文本。
3. **长篇 AI 记忆**：现有召回以词法相关度为主，需增加分层摘要、未闭合线索、权威事实提升和流式可取消生成。
4. **正文一致性**：主一致性扫描尚未完整覆盖章节正文、人物知识状态、跨章节时间矛盾和伏笔回收。
5. **正式出版导出（G10 已完成）**：支持 DOCX、PDF、EPUB、目录、封面、样式与全书/单卷/自选章节范围。

### P1：连续创作工作流

1. 将“书籍 -> 卷 -> 章 -> 场景”从制作里程碑中拆成独立文稿树，支持拖动、拆分、合并和章节级差异恢复。
2. 建立场景间、任务间和章节间的全局剧情流，共用结构化条件、效果、变量和跨场景测试。
3. 增加自定义实体类型、实体封面/图库、统一标签管理、资源合集与使用位置。
4. 将 15 个工作区归并为写作、世界、制作、项目四组，并保留最近打开、收藏、前进/后退和全局命令。

### P2：进阶能力

1. 自定义幻想历法与可缩放连续时间轴。
2. 关系图保存布局、固定节点和图片/PDF 导出。
3. 正文批注、修订建议、写作目标和每日统计（G10 已完成）。
4. 拆分超大型 `page.tsx`、`MapWorkspace.tsx` 和 `globals.css`，降低持续扩展的回归成本。

## 已完成的大目标

**G5：完整工程包与资源安全。**

交付边界：

- 自包含 `.wcodex`：清单、项目数据和资源二进制。
- 流式 ZIP64 读写、SHA-256、大小校验、路径防穿越、未声明条目拒绝和原子替换。
- 旧 `.wcodex.json` 兼容，缺失资源保留诊断而不静默丢数据。
- 内容寻址与重复资源复用，资源缺失/变化检查、重定位和替换。
- 高频快速数据快照与完整工程备份分层，恢复前冲刷保存并阻止迟到写入覆盖。
- 干净用户目录往返、故障注入、1000 资源压力和完整发布回归。

完成结论：

- 单元与故障注入 36 项断言、12 个场景通过；1000 条逻辑资源压力门禁 15 项断言通过。
- 开发版和打包版分别完成 31 项断言、3 次启动的干净目录往返；删除源目录后仍可恢复数据、资源和地图 URL。
- 既有 Electron 冒烟 400 项断言、SQLite/迁移/性能、便携冷启动和 2.1 覆盖升级全部通过。
- 便携版与安装版已生成并记录 SHA-256；完整验证见 `validation/G5_PROJECT_PACKAGE_VALIDATION.md`。

**G6：长篇文稿核心与稳定引用。**

交付边界：

- 独立书籍、卷、章、场景数据与三栏文稿工作台，支持拖动排序、拆分、合并、字数目标、状态和专注编辑。
- 文稿对象级 SQLite 历史、差异恢复、schema 16 到 17 迁移、备份和 `.wcodex` 完整往返。
- 带对象 ID、类型和世界 ID 的富文本引用节点，兼容旧 `[[标题]]`，覆盖改名、重名、失效和跨世界诊断。
- 全书、卷、章、场景分层 AI 摘要，作者确认事实和未闭合线索优先；可取消 SSE 长文生成保留部分结果。
- 人物知识状态、章节时间、伏笔提出与回收的一致性检查，可定位并打开原文对象。
- 文稿工作区拆成树、写作面板和检查器组件，并接入全局搜索、发布净化和桌面回归。

完成结论：

- 领域、引用、AI、发布、SQLite、迁移、压力与性能测试全部通过；schema 17 覆盖 9 条升级路径。
- Electron 冒烟通过 402 项断言和正常/异常退出后的 3 次启动，文稿写入与稳定引用已从 SQLite 反查确认。
- Windows x64 便携版和安装版的发行验证记录见 `validation/G6_MANUSCRIPT_RELEASE_VALIDATION.md`。

## G6 收口时发现的问题

### 下一批产品风险

1. **出版交付不足（G10 已完成）**：现已支持 DOCX、PDF、EPUB、目录、章节范围、封面和样式导出。
2. **批注与修订不足（G10 已完成）**：现已支持批注线程、修订建议接受/拒绝、作者回复和写作目标统计。
3. **语义召回增强（G10 已完成首版）**：现有完全本地的概念与文本相似度召回会显示来源、权威和命中理由，并支持按写作目标排除；通用嵌入模型不进入当前发布依赖。
4. **备份容量策略固定**：当前快速快照保留 20 个、完整备份保留 5 个，后续应增加磁盘预算、可配置保留期和一键清理预览。

### 工程与发布风险

1. `app/page.tsx` 约 16,993 行、`app/components/MapWorkspace.tsx` 约 8,311 行、`app/globals.css` 约 18,872 行；G6 已把文稿 UI 拆成树、写作面板和检查器，但页面状态编排、地图与样式仍需要继续按工作区和领域拆分。
2. 测试脚本已覆盖工程包、文稿树、稳定引用、桌面交互和公开发行门禁；远程 Windows CI 已定义，仍需在真实仓库中启用并保护发布环境。
3. Windows x64 候选产物尚无可信代码签名；占位项目署名不会替代真实法律主体，公开分发前仍需由发行者提供身份、HTTPS 地址和证书。
4. `.wcodex` 为完整但未加密的创作工程；需要秘密项目时，可增加可选口令加密，但不能把 API Key 混入工程包。
5. macOS、Linux、ARM64、云同步和实时冲突合并仍不在当前发布范围。

**G7：公开发布补全。**

交付边界：

- NSIS 安装版稳定/候选更新通道、显式下载、安装前保存冲刷、失败保留现有版本；便携版明确保持手动更新。
- 公开发行输入门禁、代码签名强制、首启条款接受、HTTPS 外链与更新源约束。
- CSP、权限拒绝、导航限制、可信 IPC、Electron fuses、ASAR 完整性边界。
- 第三方许可正文、生产依赖清单、CycloneDX SBOM、秘密与漏洞扫描、SHA-256、签名状态和构建来源清单。
- 本地一键发布门禁与 Windows CI/草稿发布工作流；候选模式不会虚构发行主体或跳过证书。

完成结论：

- 公开模式只在真实发行主体、法律/支持地址、双更新源和签名证书全部存在时运行；当前无外部输入的构建明确标记为未签名候选版。
- 详细验证与外部阻塞见 `validation/G7_PUBLIC_RELEASE_VALIDATION.md` 和 `docs/PUBLIC_RELEASE_INPUTS.md`。

**G8：全局 UI 收敛。**

交付边界：

- 主导航按写作、世界、制作和项目分组，低频工作区不再长期挤占主栏。
- 知识库、长篇文稿和 AI 工作台的目录、正文、资料与检查栏改成按需开合，窄屏使用有边界的抽屉。
- 保留地图、关系、任务和长篇编辑的专业能力，不以减少功能代替降低使用门槛。

完成结论：

- 桌面和窄屏关键视图无页面级横向溢出，验证记录见 `validation/G8_UI_CONVERGENCE_VALIDATION.md`。

**G9：多世界生命周期与删除安全。**

交付边界：

- 顶栏世界菜单提供完整复制与安全删除，不再要求用户通过导出再导入来制作项目分支。
- 复制覆盖条目、任务、剧情、地图子资源、时间线、文稿、关系、AI 记忆与项目设置，并重新映射对象 ID 和内部引用。
- 删除必须输入完整世界名称；删除前强制生成包含全部世界与本地资源的 `.wcodex` 工程备份，备份失败时不改动当前数据。
- 删除只清理目标世界及其地图子资源的数据库记录，本地资源文件保留，避免共享资源和误删风险。
- 生命周期覆盖表接入发布门禁；未来新增 `WorkspaceData` 集合却未声明复制/删除归属时测试直接失败。

完成结论：

- 领域测试覆盖 70 条断言；Electron 自动化验证复制、引用重映射、键盘确认、完整备份、SQLite 删除和重启持久化。
- 实施与截图记录见 `validation/G9_WORLD_LIFECYCLE_VALIDATION.md`。

**G10：出版、批注与写作节奏。**

交付边界：

- 选择书籍、卷或章节范围导出 DOCX、PDF 和 EPUB，生成目录、页眉页脚、封面和可复用样式模板。
- 增加不修改正文的批注线程、修订建议、接受/拒绝和作者回复，并完整纳入历史、备份与工程包。
- 增加每日字数、目标、连续写作和章节进度视图，保持安静且不游戏化过度。
- 为 AI 增加可选本地语义召回，显示每条召回的来源、层级和采用理由，并允许作者按目标排除或恢复。

完成结论：

- DOCX、PDF、EPUB 在 Electron 主进程本地生成，文件名防覆盖、封面读取限制在资源目录，出版净化移除批注、写作历史、AI 记忆和开发者私有数据。
- 批注、修订、回复、每日目标与净字数已接入对象级 SQLite 自动保存，并通过正常和异常退出恢复路径验证。
- AI 召回默认启用本地语义相似度，可逐会话关闭；结果显示来源、置顶/确认/草稿权威、相关度和具体命中理由。
- 详细实现与自动验证见 `validation/G10_MANUSCRIPT_PUBLICATION_VALIDATION.md`。

## 推荐的下一个长目标

**G11：工程模块化与大型项目长期维护。**

- 继续拆分 `page.tsx` 的资源、备份、导出和 AI 编排状态，将工作区写入边界移入可测试的领域控制器。
- 拆分 `MapWorkspace.tsx` 的画布、图层、交互工具和检查器，降低地图能力继续扩展时的回归面积。
- 按工作区拆分累积样式并建立视觉令牌检查，减少全局选择器互相影响。
- 为快速快照与完整备份增加磁盘预算、保留期和清理预览，避免长期创作机器被静默占满。

## 明确不进入当前路线

- 社区、关注、动态和公开发现。
- 插件市场与第三方插件生态。
- 游戏引擎专用同步或直接导入。
- 实时多人协作和云端账号体系。

这些能力不会早于数据安全、长篇写作、AI 记忆和全局剧情闭环。
