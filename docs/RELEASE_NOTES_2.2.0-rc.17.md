# Worldcraft Codex 2.2.0-rc.17

## AI 项目操作：作者工作区全覆盖

- 内置 AI 项目操作新增世界设置、项目分类、条目模板、测试预设、审阅问题、资源元数据和成员权限七类目标；现在可在同一原子事务里编排项目结构、内容、测试、协作、地图与制作计划。
- 条目操作新增 `categoryId`、`templateId` 和 `templateData`，可直接使用本批创建的分类与模板；测试预设的变量状态键也支持批内短引用。
- 操作上下文新增分类层级、模板定义、测试预设、审阅问题、资源元数据和成员角色，并继续排除秘密模板值、本地资源路径、成员账号与制作备注。
- 操作台新增“项目”和“测试”计数；示例任务覆盖分类、模板、测试预设和审阅问题，1440 与 1100 像素宽度下保持无横向溢出。

## 原子校验与安全边界

- 分类层级循环、失效分类、使用中模板删除、模板字段错误、测试场景和变量类型、审阅关联、资源条目关联、成员账号重复与唯一所有者均在写入前统一校验；任一错误会回滚整批事务。
- 世界目标只允许更新当前世界的名称、说明和可见性；资源目标只允许修改已导入文件的名称、分类、标签、备注和条目关联。
- 资源文件、文件名、路径、MIME、大小、测试运行结果、一致性扫描和凭据不可由 AI 创建、删除或伪造；成员账号只有在用户指令明确写出时才可提交。
- AI 新建的审阅问题固定为人工来源，模型不能伪造测试运行、分析或一致性扫描来源；内置模板不可删除，世界始终保留至少一名所有者。

## 审计、撤销与导入

- 点击审计记录可精确打开世界权限、分类编辑弹窗、模板工坊、测试预设、审阅问题、资源详情和成员权限，并保留现有地图、制作与时间线定位能力。
- 分类与条目顺序在提交前按工作区规则归一化，自动顺序变化也进入审计；重启后不会因重新编号而失去一键撤销能力。
- 撤销比较改为 JSON 语义比较：对象键顺序不影响判断，数组顺序和真实字段变化仍严格保护；发生作者后续修改时会列出变化字段并拒绝覆盖。
- 导入项目时，新增目标的审计 ID 会随世界、分类、模板、测试预设、审阅问题、资源和成员一起重映射；数据库 schema 保持 `16`。
